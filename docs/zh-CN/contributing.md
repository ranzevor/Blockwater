# Blockwater 贡献指南

[English](../../CONTRIBUTING.md)

提交 PR 前，请先查看现有 Issue 与[实施里程碑](../milestones.md)，明确希望改变的行为、验收条件和受影响的模块。一个 PR 尽量聚焦于通信协议、宿主适配、图形融合、文档或国际化中的一项具体目标。

1. 从最新默认分支创建工作分支，不要在功能变更中混入无关的格式调整或目录移动。
2. 按 [README](../../README.zh-CN.md) 构建并运行测试，并执行 `python3 tools/validate_repository.py` 检查文档和语言资源。
3. 修改协议、生命周期、事件顺序、方块代理或合成算法时，添加相应回归测试；不兼容的协议布局变更必须更新 `kVersion`，并处理两端的版本拒绝。
4. 在 PR 中列出实际验证的环境、结果以及尚未验证的部分。模拟宿主通过不等于 RDR2 或 Minecraft 实机兼容。
5. 说明新增依赖的来源和许可。禁止提交游戏专有资源、提取资产、游戏二进制、存档、专有 SDK 二进制、无合法许可的外部源码、凭据和私人设备路径。

游戏原生操作须在经过验证的游戏脚本线程执行，不得因 IPC 或文件操作阻塞每帧执行。RDR2 插件在任何改写游戏世界的操作之前必须拒绝多人模式；连接断开时必须清理本项目创建的宿主对象。Native 哈希及签名须有可核验来源，并在声明兼容性之前针对目标版本实际验证。

Bug 报告应包括复现步骤、预期与实际结果、系统及工具链／游戏版本，以及已经脱敏的相关诊断信息。安全漏洞请按[安全报告指引](security.md)私下报告，不要公开漏洞细节。

新增消息键须同步更新 `en-US` 和 `zh-CN` 资源，保持键名稳定，翻译真实业务语义，详见[国际化规范](localization.md)。维护者审核代码行为、协议兼容、资源权利、回归证据及最终用户文字；CI 不能替代实机验收与授权审查。
